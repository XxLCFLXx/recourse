# recourse

> **Every agent decision should come with a receipt, a deadline, and an undo button.**
> 每个 agent 的决定，都该有一张收据、一个期限、一个撤销键。

你有日志。你有总闸。
你没有收据，也没有撤销键。

---

## 这和 kill switch、审计日志、human-in-the-loop 有什么不同？

这三样行业都做完了。它们各解决一半，合起来还是缺一环。

| 已有的 | 它解决什么 | 它答不上什么 |
|---|---|---|
| **Kill switch / 熔断** | 能不能**整个**关掉 | 能不能只翻掉**一条**判决 |
| **Audit log / trace** | 过去**发生了什么** | **谁**为它负责、到**哪天**为止 |
| **Human-in-the-loop 审批** | 事前**允不允许**做 | 做完之后**判错了怎么办** |
| **recourse** | 一条判决**由谁负责、多久内能翻、怎么撤** | — |

三个具体差别：

- **总闸停的是全部**，代价是自己给自己来一次拒绝服务。上诉停的是**一条**。
- **日志是只读的、没有地址的**。判决记录必须有一个人的邮箱，和一个**到期日**。
- **审批门在事前，上诉窗口在事后。** 它们是两个时态的东西。

一句话：**它们管「能不能做」，这个管「做错了谁答」。**

2026 年这个领域已经很挤：审批门、哈希链、决策 BOM、回滚轨道，全都有人做。

空着的是一个格子：**责任**。

到现在还没有一个格式，把「一个事先同意的、可被追究的真人」当成必填字段。
这个项目就是那个格子。

## 四条不变量

| | | 为什么 |
|---|---|---|
| **I1 可中断** | 任意在途判断可被外部中止，且沿传播链生效 | 唯一真正握有权力的一条 |
| **I2 可归因** | 每条判断终止于一个**具名的人**，不是角色、不是 agent | 机器身份不是归因 |
| **I3 可替换** | 判断组件可被换掉，系统降级而不崩 | 能换掉，不透明就不致命 |
| **I4 回避** | 判断者不得是被判断者 | 最新、最便宜、最没人做的一条 |

I1 和 I2 是全有或全无。缺一条，其余三项的意义有限。

## 两个工具

```bash
# 测一条判决记录
python appeal_check.py verdict.json

# 测一个系统
python conformance.py recourse.yaml

# 生成空白声明
python conformance.py --init
```

`conformance.py` 只给四个判定之一，**不给分数**：

| 判定 | 含义 | exit |
|---|---|---|
| `ANSWERABLE` | 四项齐备 | 0 |
| `STALLED` | 能停、能追责，但翻不了案 | 1 |
| `NON_APPEALABLE` | 停不下来，或停下了没人接手 | 2 |
| `UNPROVEN` | 有检查还没有人签字 | 3 |

> 分数会被优化，判定不会。

## 三档证据

| 档 | 谁给的 | 例 |
|---|---|---|
| **声明** | 你的配置 | 有没有中止入口 |
| **实测** | 探针跑出来的 | 中止后还有没有残留效果 |
| **签字** | **一个真人** | T_stop 的实测数字 |

待签字的项会**挡住**最高判定。
你没法靠自动化把自己刷过去——这正是它唯一值钱的地方。

---

## 它不做什么

- 不让 AI 变聪明
- 不让 AI 变安全
- 不解决对齐
- 不解决「谁上诉上诉者」

它只做一件事：**让 AI 犯错之后，有人接得住。**

## 如果你是在搜这些

`agent kill switch` · `agent audit trail` · `human-in-the-loop approval` ·
`agent rollback` · `AI accountability` · `agent guardrails` · `agent observability`

它们解决的是**事中**：做之前拦一下，做完之后记一笔。

这个项目补的是**事后**那一段——判决已经生效、有人不认、需要一个说法的时候。
